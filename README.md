# CallRecorder 実機検証版 0.1.0

Windows 11で、選択したマイクと再生デバイスの音声を別々のWAVへ保存するコンソールアプリです。添付の基本設計書 v0.3を基に実装しました。実機試験済み・MVP受入完了という意味ではありません。

## 起動する

1. PCの「設定 → システム → バージョン情報 → システムの種類」を確認します。Intel/AMDの64ビットPCは **win-x64**、ARMベースのPCは **win-arm64** を使用します。
2. 対応するZIPをユーザーフォルダーに展開してください。
3. `Start-CallRecorder.cmd` をダブルクリックします。PowerShellの場合は `./CallRecorder.exe` でも起動できます。
4. 初回に設定ファイルが自動作成されます。Windowsの「設定 → プライバシーとセキュリティ → マイク」で、デスクトップアプリのマイクアクセスを許可してください。

ランタイム同梱のため、.NETの別途インストールや管理者権限は不要です。実行ファイルは未署名です。Windowsの保護機能で実行を止められた場合は、組織の配布ルールに従って確認してください。

| 操作 | 動作 |
|---|---|
| D | 入出力デバイスの名前・ID・状態・両既定ロールを表示。音声ストリームは開かない |
| T | 選択出力に440Hzの小音量テスト音を2秒再生、マイクピークを表示。ファイル保存なし |
| R | 設定を再読込、選択デバイスを確認、同意確認。明示Yだけで録音開始 |
| S | 両系統を停止し、残データを保存 |
| Q / Ctrl+C | 停止・保存を待って終了 |

開始・停止処理中のS/Qも受け付けます。開始中の停止要求は開始の後処理を待って適用されます。ディスクI/Oが長く停滞している場合、終了は書き込み完了を待つため5秒を超えることがあります。

**会議アプリでミュートしても本アプリのマイク収録は続きます。独り言や周囲の会話も保存され得ます。選択した出力デバイスで再生される他アプリの音も収録対象です。** 会議アプリのミュート状態は未取得です。必要な通知・同意を得た上でYを選択してください。本アプリから参加者へ自動通知はしません。

Teams、Zoom、Chrome、Edge、Firefoxのプロセスは候補表示だけに使います。会議への参加状態を検出せず、自動録音・候補消失での自動停止もしません。

## 設定と保存先

設定: `%LOCALAPPDATA%\CallRecorder\settings.json`

録音: `%LOCALAPPDATA%\CallRecorder\Recordings`

イベントログ: `%LOCALAPPDATA%\CallRecorder\Logs\events.jsonl`

`settings.example.json` を参考に、**停止中に**設定を編集してください。キー名はcamelCaseです。アプリ配置フォルダーのsettings.example.jsonを編集しても設定は変わりません。

- `captureDeviceId` / `renderDeviceId`: Dで表示した正確なID。nullは通信ロールの既定。明示IDが無効なら開始しません。
- `recordingDirectory`: nullは既定、独自パスではJSONのバックスラッシュを `\\` とします。ローカルディスク推奨。ACLの広いグループ権限を検査・警告します。
- `deviceConfiguration`: 例「同一USBヘッドセット」「USBマイク＋内蔵出力」。機器構成別の評価用。
- `segmentMinutes`: 既定30、30より大きくできません。短い分割試験には0.1（6秒）を指定できます。
- `maxSegmentDataBytes`: 既定・最大1GiB。片方の形式が上限に達する時間を共通境界として両音源に適用します。
- `queueCapacitySeconds` / `queueWarningSeconds`: 既定30秒 / 15秒。形式に応じたバイト上限を計算します。
- 開始時に2GiB、録音中は5秒ごとに512MiBの空き容量を確認します。収録予定時間分の容量を別途確保してください。

WAVは取得した形式を保持し、圧縮・混合しません。48kHz/2ch/32bit floatの場合、1系統だけで約1.38GB/時です。

セッションごとに `yyyyMMdd_HHmmss_fff_GUID` フォルダーを作成し、`000001_mic.wav` と `000001_speaker.wav`、`session.json` を保存します。録音中は `.wav.partial` です。両音源の当該分割ファイルが正常に確定してから `.wav` へ改名します。失敗したセッションには既に確定した正常セグメントと未完了セグメントが混在する場合があります。セッション全体の結果はsession.jsonのstatusを確認してください。

強制終了の次回起動では未完了ファイル・メタデータを通知するだけで、修復・改名・切詰め・削除はしません。WAVが再生できる場合でも、未完了ファイルを完全保存と扱わないでください。

## 実装した保存・障害対策

- 音声コールバックではデータのコピーとキュー投入だけを実施。単一の保存タスクが両音源のファイルを所有。
- 音源別30秒相当のキュー。上限超過はエラー停止し、黙ってデータを捨てて成功扱いしない。
- 2秒ごとにWAVヘッダー更新、10秒ごとにFileStream.Flush(true)を要求。遅延時間・最大キュー量を記録。
- 30分または1GiB以内の共通時間境界をサンプルフレームへ丸めて分割。境界をまたぐブロックも分配。
- 承認後だけ同じ出力へ無音再生。2秒データ未着で警告、5秒未着で両系統停止。
- キャプチャ停止イベントは3秒でタイムアウト。タイムアウト・保存失敗は失敗として記録。
- 開始呼出前後・初回受信時刻・Stopwatch周波数・取得フレーム数を記録。
- 各開始呼出の共通開始基準からの差を先頭無音で補填。開始差2秒超は開始失敗。正常停止時の末尾差250ms以内のみ短い無音補填を行い、量を記録。250msは機器同期の合格基準ではありません。
- 途中欠落の推定補填、機器クロックの補正、精密同期、自動修復は未実装。
- 音声データをネットワークへ送信する処理はありません。

## 実機検証

最初に `実機検証手順.md` の短時間試験を行い、次に60分・4時間試験へ進んでください。`実機検証結果.csv` に機器・OS・結果を記録できます。

Linux環境で保存処理の自動テストとWindows向けクロスビルドを行っています。Windowsの起動、WASAPI、実デバイス、会議アプリ、Bluetooth、停止時間、長時間収録は未検証です。

## ソースからビルド

.NET SDK 10を使用します。NAudio.Wasapi 2.2.1（Coreを依存として使用）に固定しています。.NET 8は2026-11-10にサポート終了予定のため、本検証版は.NET 10 LTSへ変更しました。自己完結版のランタイム更新には再ビルドが必要です。

```powershell
dotnet test ./tests/CallRecorder.Tests.csproj -c Release
dotnet publish ./src/CallRecorder.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:DebugType=None -p:DebugSymbols=false -o ./publish/win-x64
```

ARM PC向けは `-r win-arm64` に変更します。`build.ps1` はテスト後に両アーキテクチャをビルドします。NAudioはMITライセンス、.NETのライセンスは同梱資料を参照してください。
